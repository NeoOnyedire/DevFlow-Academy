## ✅ Resolved since last pass
- **Full account deletion shipped.** `api/admin/[action].ts`'s `delete-account` action removes the Redis user record (via `deleteUser` in `api/_lib/users.ts`) plus every dependent Postgres row (`user_progress`, `lesson_progress`, `leaderboard_entries`) in one shot, logged to `admin_actions`. `AdminPage.tsx` has a "Delete account" button per user with a confirm dialog. This closes the GDPR-style hard-delete gap from the previous pass.
- **AI-moderation rejections are now in the audit trail.** `api/moderate-review.ts`'s `logRejection()` writes every AI-rejected review to `admin_actions` (action: `ai-review-rejected`, with rating/comment/reply in `details`), so a wrongly-rejected genuine review can now be traced after the fact — previously only manual admin overrides were logged.
- **One-time admin user-list backfill has a real trigger.** `backfillAllUsersSet()` (SCANs Redis for `devflow:user:*` and adds any missing id to `devflow:all-users`) is wired to a `backfill-users` admin action and a "Backfill user list" button on `AdminPage.tsx` — no longer just a "worth adding" note, it's live and safely re-runnable.
- **Basic admin search added.** `AdminPage.tsx` now has a client-side search box over the users table (name, email, GitHub username), addressing part of "admin panel is functional, not pretty." Pagination is still absent — see below.
- **Admin dashboard is live.** A single-account-gated `/admin` page (server-enforced via `api/_lib/admin.ts`) lets the admin see every registered user, wipe a user's entire course progress, toggle a user's "has reviewed" flag, delete individual reviews (including legacy ones), and delete or bulk-reset leaderboard entries by week.
- **Admin actions are logged.** Every destructive admin call writes a row to `admin_actions` (best-effort — a logging failure never blocks the actual action).
- **Users became enumerable** via the `devflow:all-users` Redis set, now backfillable on demand (see above) rather than only growing on login.
- **Reviews got stable ids**, with legacy index-based delete fallback for pre-existing reviews.
- **Real backend is live.** Auth, sessions, reviews, progress, and leaderboard data run server-side through Vercel Functions, Upstash Redis, and Postgres.
- **Error boundaries added**, split by variant (`page` vs `overlay`).
- **Real 404 page.**
- **Email verification + password reset**, with rate limiting and generic responses.
- **GitHub OAuth**, full authorization-code flow with CSRF state check and secure session creation.
- **Gitter chat persistence** in `sessionStorage`, cleared on logout.
- **`GitterHelper`'s index bug is fixed.**
- **Real SQL leaderboard**, ranked via `RANK() OVER (...)`.
- **Server-side progress syncing** across devices via Postgres `user_progress`.
- **Dynamic auth routing**, consolidated into one function to stay under the Hobby-plan Serverless Function cap.
- **Single-use verification and reset tokens.**
- **Database schema introduced** — Postgres for leaderboard/progress, Redis for sessions/users/tokens.
- **Email/password login paused, GitHub-only for now**, behind a single `EMAIL_LOGIN_ENABLED` flag.
- **GitHub OAuth callback deep-link bug fixed** (`vite.config.ts` `base: '/'`).
- **Added `vercel.json` SPA rewrite** excluding `/api/*`.
- **Three AI providers for Gitter AI (BYOK)** — Gemini, Groq, Anthropic — via shared `api/_lib/aiProviders.ts`.
- **AI-moderated reviews** via `api/moderate-review.ts`, fails open on provider hiccups.
- **Gitter AI activation required for course completion**, gating Module 1 completion.
- **Privacy policy updated** to reflect AI-moderated reviews, the three BYOK providers, and Anthropic's non-free-forever pricing.

## 🔴 Fix first: remaining data issues

- **Email login is paused, not removed — still needs a real decision.** `EMAIL_LOGIN_ENABLED = false` remains a stopgap pending a stable custom domain. The GitHub OAuth callback URL is still pinned to `dev-flow-academy.vercel.app` — revisit if a custom domain is added.
- **Gitter AI is still a hard requirement, not just an upgrade.** It gates both course completion and reviews, so learners without a Gemini/Groq/Anthropic account (or a card, for Anthropic-only users) hit a wall at Module 1. The gate in `CurriculumPanel.tsx`'s `finishLesson` is still a single `if` block and easy to relax (e.g. gate only the review) if this proves too much friction. Worth instrumenting drop-off before deciding.
- **GitHub profile connection is still browser-specific.** GitHub OAuth accounts work correctly, but linking an existing password account to GitHub isn't persisted separately yet.
- **No audit/event logging for non-admin actions.** Registrations, password resets, and logins still aren't logged anywhere for debugging or analytics — only admin-initiated destructive actions and AI-rejected reviews are, via `admin_actions`.
- **Rate limiters are still fragmented.** `api/_lib/rateLimit.ts`, `api/gitter.ts`, and `api/reviews.ts` each implement their own in-memory rate limiting. A shared Redis-backed implementation would survive serverless cold starts and simplify maintenance. (`api/admin/[action].ts` intentionally has none — single trusted account.)
- **Admin panel still has no pagination.** Search now exists (see Resolved), but the users/reviews/leaderboard tables will get unwieldy at real scale without it.

## 🟠 Architecture/robustness

- **Redis and Postgres are tightly coupled throughout the API layer.** Repository/service abstractions would ease future storage migrations.
- **Authentication logic is repeated.** Multiple endpoints manually call `getUserIdFromRequest()` and `getUserById()` instead of sharing middleware. `requireAdmin()` is a step toward this but only covers the admin case.
- **Request validation is handwritten everywhere.** Zod or Valibot could reduce duplicated validation code.
- **No centralized API error handler.** Nearly every endpoint repeats similar `try/catch` blocks.
- **No API versioning.** `/api/v1` would ease future breaking changes.
- **No OpenAPI/Swagger documentation.**
- **Lazy-load routes.** `App.tsx` still imports every page eagerly, including `AdminPage`, which every visitor's bundle includes even though only one account can use it. `React.lazy` + `Suspense` would help; `/admin` is the obvious first candidate.
- **No loading skeletons** for GSAP-heavy pages during first paint.
- Allow users to edit or delete their own reviews.
- Show "Last synced" status for course progress.
- Add profile avatar customization.
- Add account settings page (beyond theme).
- Cache leaderboard responses using HTTP cache headers.
- Cache course metadata to reduce repeated API requests.

## 🟡 UX polish

- **Gitter AI doesn't stream.** Responses arrive all at once instead of token-by-token.
- **Certificates are still conceptual only.** No actual downloadable certificate on course completion.
- **Dashboard streak, badges, and rankings are still simplified placeholders**, calculated with basic heuristics rather than real activity history.
- **No user profile page** showing achievements, certificates, completed modules, leaderboard history, or linked GitHub account in one place.
- **No notification system.** Success messages disappear instead of a persistent notification center.
- **No optimistic UI updates.** Reviews, leaderboard submissions, progress updates, and admin actions all wait for a server round-trip.
- **Review moderation feedback could be clearer.** A rejected review just shows the AI's reply as an error — a "revise and resubmit" state keeping the draft text visible would feel less like a dead end.
